H&S Incidents: Feature Flag for BBS Record Types

Context

TPR gates features using boolean flags in company_settings, checked by custom middleware per module. There is no requirePlan middleware — look at requireRaBuilderFeature in server/routes/raBuilder.ts lines 12–23 for the exact pattern to follow.

Good Spot and Positive Action record types are currently available to all customers. They need their own feature flag so the platform admin can selectively enable BBS reporting for Pro/Max customers at signup.

1. Add featureBbs to company_settings schema

In server/isolatedSchema.ts, find the feature toggles block (around line 505–527 — search for featureRaBuilder). Add this line near the other H&S feature flags:

featureBbs: boolean("feature_bbs").default(false),

Place it after featureHsIncidents (line ~518). Default is false — platform admin enables it per customer.



2. Add feature flag middleware to server/routes/hsIncidents.ts

Add this middleware function near the top of the file, following the exact same pattern as requireRaBuilderFeature in raBuilder.ts:

import { simpleDatabaseService } from '../simpleDatabaseService';

const requireBbsFeature = async (req: any, res: any, next: any) => {
  try {
    const context = simpleDatabaseService.createCustomerContext(req.user!.username, req.customerId);
    const settings = await simpleDatabaseService.getCompanySettings(context);
    if (!settings?.featureBbs) {
      return res.status(403).json({ error: 'Good Spot and Positive Action reporting is not enabled for your account. Please upgrade to TPR Pro or contact support.' });
    }
    next();
  } catch (error) {
    next(error);
  }
};

If simpleDatabaseService is already imported in hsIncidents.ts, don't add it again.
