You are extending TPR Max — a site compliance SaaS platform built in 
Node.js (Express) with a React frontend and PostgreSQL database — with 
a full HR module linked to the existing staff module.

The staff module is the single source of truth for every person. All HR 
features read from and write to the existing staff record. Do not create 
a parallel people system — extend what exists.

Work through each section in order. Do not skip ahead. All database 
changes must use IF NOT EXISTS or ADD COLUMN IF NOT EXISTS — the platform 
is live with real customer data.

SECTION 2 — RIGHT TO WORK
════════════════════════════════════════════════════════════════════

LEGAL CONTEXT:
Employers must check and record evidence that every employee has 
the legal right to work in the UK before employment begins, under 
the Immigration, Asylum and Nationality Act 2006. Employing someone 
without the right to work carries a civil penalty of up to £60,000 
per worker and potential criminal prosecution.

This feature links directly to site access — an expired Right to 
Work document should flag at the QR check-in.

STEP 2A — DATABASE: Right to work table
────────────────────────────────────────────────────────────────────

  CREATE TABLE IF NOT EXISTS right_to_work (
    id                  SERIAL PRIMARY KEY,
    staff_id            INTEGER NOT NULL REFERENCES staff(id) 
                          ON DELETE CASCADE,
    customer_id         INTEGER NOT NULL REFERENCES customers(id),
    document_type       TEXT NOT NULL,
      -- Values: 'uk_passport' | 'eu_settled_status' | 
      --         'biometric_residence_permit' | 'share_code' |
      --         'visa' | 'certificate_of_naturalisation' | 'other'
    document_reference  TEXT,
      -- Passport number, BRP number, share code etc
    issue_date          DATE,
    expiry_date         DATE,
      -- NULL for indefinite leave to remain / British citizens
    verified_date       DATE NOT NULL,
      -- Date the employer checked the document
    verified_by         TEXT NOT NULL,
      -- Name of the person who carried out the check
    verification_method TEXT NOT NULL DEFAULT 'manual',
      -- Values: 'manual' | 'idsp' 
      -- (IDSP = Identity Service Provider — digital check)
    document_url        TEXT,
      -- Scanned copy of the document (stored securely)
    notes               TEXT,
    is_current          BOOLEAN DEFAULT TRUE,
      -- FALSE when superseded by a new document
    reminder_sent_at    TIMESTAMPTZ,
    created_at          TIMESTAMPTZ DEFAULT NOW()
  );

STEP 2B — BACKEND: Right to Work routes
────────────────────────────────────────────────────────────────────

  GET    /api/staff/:staffId/right-to-work
    — Returns current RTW record for this staff member

  POST   /api/staff/:staffId/right-to-work
    — Create new RTW record. Sets previous records is_current = FALSE.

  POST   /api/staff/:staffId/right-to-work/:id/upload
    — Upload scanned document (PDF or image)

  GET    /api/right-to-work/expiring
    — Returns all RTW documents expiring within 90 days across 
      all staff, ordered by expiry_date ascending.
      Excludes documents with NULL expiry_date.

  GET    /api/right-to-work/status/:staffId
    Returns:
    {
      hasRTW: boolean,
      isExpired: boolean,
      daysUntilExpiry: number | null,  -- null if no expiry
      isVerified: boolean,
      blocksAccess: boolean  -- true if expired AND has expiry date
    }

SITE ACCESS INTEGRATION:
In the existing QR check-in endpoint (wherever staff check-in 
is processed), add a Right to Work check:

  1. Look up the staff member's current RTW record
  2. If no RTW record exists: allow entry but add warning flag 
     to check-in response: 
     { warning: 'no_rtw_on_record', message: 'No Right to Work document recorded' }
  3. If RTW has an expiry date and it has passed: 
     { blocked: true, reason: 'rtw_expired', message: 'Right to Work document expired — entry not permitted' }
  4. If RTW expires within 30 days: allow entry but warn:
     { warning: 'rtw_expiring_soon', daysRemaining: N }

The kiosk UI should display these warnings clearly to the 
site receptionist.

STEP 2C — BACKEND: RTW reminder cron job
────────────────────────────────────────────────────────────────────

Add to the daily cron job. Find all RTW documents where:
  - is_current = TRUE
  - expiry_date IS NOT NULL
  - expiry_date <= NOW() + INTERVAL '90 days'
  - reminder_sent_at IS NULL OR 
    reminder_sent_at < NOW() - INTERVAL '30 days'

Send email to customer HR admin:

  Subject (expiring): "⚠ Right to Work Document Expiring — [STAFF NAME]"
  Subject (expired):  "🚨 Right to Work Document EXPIRED — [STAFF NAME]"

  Body:
  ---
  The Right to Work document for [STAFF NAME] 
  [is expiring on DATE / expired on DATE].

  Document type: [TYPE]
  Reference: [REFERENCE]
  Expiry date: [DATE]
  Originally verified: [DATE] by [VERIFIED BY]

  You must obtain and verify a new document before or 
  immediately after the expiry date. Continuing to employ 
  someone without valid Right to Work evidence may result 
  in a civil penalty of up to £60,000.

  Log in to TPR Max to upload the renewed document.
  ---

Create /server/utils/leaveUtils.ts:

  export function calculateWorkingDays(
    startDate: Date,
    endDate: Date,
    workingDaysPerWeek: number = 5
  ): number {
    -- Count calendar days between start and end (inclusive)
    -- Subtract weekends (Sat/Sun)
    -- If workingDaysPerWeek < 5, pro-rate accordingly
    -- Do NOT subtract bank holidays automatically 
    --   (bank holidays vary — let customer manage this manually 
    --    or add a bank_holidays table later)
    -- Return number with 0.5 precision (for half days)
  }

  export function calculateLeaveBalance(
    entitlementDays: number,
    leaveYear: { start: Date, end: Date },
    approvedLeave: LeaveRequest[]
  ): {
    entitlement: number,
    taken: number,
    pending: number,
    remaining: number
  }

STEP 5B — BACKEND: Bradford Factor utility
────────────────────────────────────────────────────────────────────

Create /server/utils/bradfordFactor.ts:

  export function calculateBradfordFactor(
    absences: AbsenceRecord[],
    rollingDays: number = 365
  ): {
    score: number,          -- S² × D
    spells: number,         -- S = number of separate absence spells
    totalDays: number,      -- D = total days lost
    rating: 'low' | 'medium' | 'high' | 'critical'
      -- low:      0–49
      -- medium:   50–199
      -- high:     200–449
      -- critical: 450+
  }

Filter absences to only those starting within the last 
rollingDays days (default 12 months).

SECTION 8 — LEAVER PROCESS
════════════════════════════════════════════════════════════════════

STEP 8A — DATABASE
────────────────────────────────────────────────────────────────────

  CREATE TABLE IF NOT EXISTS leaver_checklists (
    id              SERIAL PRIMARY KEY,
    customer_id     INTEGER NOT NULL REFERENCES customers(id),
    staff_id        INTEGER NOT NULL REFERENCES staff(id),
    last_day        DATE NOT NULL,
    reason          TEXT,
      -- Values: 'resignation' | 'redundancy' | 'dismissal' | 
      --         'end_of_contract' | 'retirement' | 'other'
    is_voluntary    BOOLEAN,
    exit_interview_completed BOOLEAN DEFAULT FALSE,
    created_at      TIMESTAMPTZ DEFAULT NOW()
  );

  CREATE TABLE IF NOT EXISTS leaver_items (
    id              SERIAL PRIMARY KEY,
    checklist_id    INTEGER NOT NULL 
                      REFERENCES leaver_checklists(id)
                      ON DELETE CASCADE,
    item_key        TEXT NOT NULL,
    label           TEXT NOT NULL,
    completed       BOOLEAN DEFAULT FALSE,
    completed_at    TIMESTAMPTZ,
    completed_by    TEXT,
    notes           TEXT,
    display_order   INTEGER DEFAULT 0
  );

Default leaver checklist items:
  1.  resignation_received    — Written resignation / notice received
  2.  last_day_confirmed      — Final working day confirmed
  3.  handover_plan           — Handover plan agreed
  4.  payroll_notified        — Payroll team notified of leave date
  5.  equipment_returned      — All company equipment returned
  6.  access_removed          — Building / system access removed
      (Auto-complete this when employment_status set to 'leaver')
  7.  tpr_max_deactivated     — TPR Max QR code deactivated
      (Auto-complete when staff record status = leaver)
  8.  p45_issued              — P45 reference number noted
  9.  exit_interview          — Exit interview completed
  10. references_agreed       — Reference process discussed

STEP 8B — BACKEND: Leaver routes
────────────────────────────────────────────────────────────────────

  POST /api/staff/:staffId/initiate-leaver
    Body: { last_day, reason, is_voluntary }
    Actions:
      1. Set staff.employment_status = 'leaver'
      2. Set staff.contract_end_date = last_day
      3. Create leaver_checklist record
      4. Populate leaver_items from leaver template
      5. Auto-complete 'access_removed' and 'tpr_max_deactivated'
         items (since status is now leaver, QR check-in will block)
      6. Cancel any approved future leave requests
      7. Send notification to HR admin and line manager

  GET  /api/staff/:staffId/leaver
    — Returns leaver checklist with completion status

  PATCH /api/staff/:staffId/leaver/items/:itemId
    — Mark item complete

  POST /api/staff/:staffId/archive
    — Called after leaver process is complete and 
      data retention period has been noted.
      Sets employment_status = 'archived'.
      Flags: GDPR retention period is typically 6 years 
      for employment records — do not auto-delete.

  CREATE TABLE IF NOT EXISTS appraisals (

      -- Values: 'annual' | 'probation' | 'mid_year' | 'informal'

  );
