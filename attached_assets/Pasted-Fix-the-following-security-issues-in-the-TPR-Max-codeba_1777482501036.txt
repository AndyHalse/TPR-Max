FIX 2 — Implement visitor emergency notification (visitors.ts)

false and does nothing.

(if provided at check-in) using the existing email service 
pattern used elsewhere in the codebase.

and check in with a Fire Marshal.

and return false gracefully (no crash).

FIX 3 — Replace Math.random() tokens with crypto.randomBytes 
(visitors.ts, contractors.ts)

Search for all uses of Math.random() used to generate tokens, 
references, or IDs. Replace each with:

  import { randomBytes } from 'crypto';
  const token = randomBytes(16).toString('hex');

This applies to visitor token generation and any contractor 
token generation that uses Math.random().

FIX 6 — Audit and fix raw SQL schema name injection 
(server/routes/platformAdmin.ts)

Search for sql.raw() calls where a schemaName variable is 
interpolated. 

Add strict validation before any raw SQL execution:
  
  // Only allow schema names matching this exact pattern
  if (!/^[a-z0-9_]{3,63}$/.test(schemaName)) {
    throw new Error('Invalid schema name');
  }

Add this validation check in every place schemaName is used 
in a sql.raw() call.

FIX 7 — Harden the development auth bypass (server/auth.ts)

Find isDevAuthBypass() or similar. Currently gated only by 
NODE_ENV === 'development'.

Add an additional explicit flag requirement:

  function isDevAuthBypass(): boolean {
    return (
      process.env.NODE_ENV === 'development' && 
      process.env.ALLOW_DEV_AUTH_BYPASS === 'true'  // must be explicitly set
    );
  }

This means even a misconfigured NODE_ENV in production cannot 
enable the bypass unless ALLOW_DEV_AUTH_BYPASS is also 
explicitly set to 'true'.
