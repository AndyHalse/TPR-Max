SECTION A — STATUTORY COMPLIANCE CERTIFICATE REGISTER
════════════════════════════════════════════════════════════════════════

PURPOSE:
Every non-domestic building has a set of legally required inspections 
and certificates. Currently there is no single place in TPR Max to 
track all of them. This module adds a "Compliance Register" — one 
dashboard showing every statutory certificate, its status, next due 
date, and uploaded document. Non-compliance with these is a criminal 
offence for the Responsible Person.

The PPM module already handles maintenance work orders. This module 
tracks the certificates those inspections produce — and statutory 
inspections that are managed externally.

STEP A6 — BACKEND: Status calculation utility

Create server/utils/complianceCertUtils.ts:

  export function calculateCertificateStatus(
    expiryDate: Date | null,
    reminderDaysBefore: number = 30
  ): 'current' | 'expiring_soon' | 'expired' | 'no_expiry' {
    if (!expiryDate) return 'no_expiry'
    const today = new Date()
    const expiry = new Date(expiryDate)
    if (expiry < today) return 'expired'
    const daysUntil = Math.ceil((expiry.getTime() - today.getTime()) 
                                / (1000 * 60 * 60 * 24))
    if (daysUntil <= reminderDaysBefore) return 'expiring_soon'
    return 'current'
  }

  export function calculateNextDueDate(
    issueDate: Date,
    frequency: string,
    customDays?: number
  ): Date | null {
    -- Follow same logic as existing calculateNextDueDate in ppm.ts
    -- Return null for 'custom' with customDays = 0 (asbestos)
  }

  export function getDaysUntilExpiry(expiryDate: Date | null): number | null {
    if (!expiryDate) return null
    const today = new Date()
    return Math.ceil(
      (new Date(expiryDate).getTime() - today.getTime()) / (1000 * 60 * 60 * 24)
    )
  }

SECTION B — PERMIT-TO-WORK SYSTEM
════════════════════════════════════════════════════════════════════

PURPOSE:
For high-risk activities (hot works, working at height, confined 
spaces, electrical isolation) carried out by contractors or staff, 
a formal Permit-to-Work must be issued and authorised BEFORE work 
begins. This is a legal requirement under the Management of Health 
& Safety at Work Regulations 1999 and is standard practice in 
facilities management, construction, and manufacturing.

TPR Max already manages WHO the contractor is and whether their 
documents are valid. This module controls WHETHER they are 
authorised to carry out specific high-risk work on a specific day.

Create server/utils/ptwChecklists.ts with predefined checklist 
items for each permit type. These are seeded into permitChecklist 
when a permit is created.

HOT WORKS checklist items:
  Section: "Area Preparation"
    — All flammable/combustible materials removed or protected
    — Fire-resistant screens/blankets in position
    — Area clear of gas cylinders and compressed gas
    — Floor swept clear of debris
    — Hot works area inspected and approved
  Section: "Fire Precautions"
    — Fire extinguisher present and appropriate type (CO₂ or dry powder)
    — Fire alarm system in this area isolated (if required)
    — Hot works fire watcher assigned and briefed (1-hour post-work watch)
    — Nearest fire point identified and accessible
  Section: "PPE"
    — Welding/grinding PPE available (face shield, gloves, apron)
    — Respiratory protection available if required
  Section: "Authorisation"
    — RAMS for hot works reviewed and accepted
    — Operative has relevant hot works training/qualification
    — Operational area evacuated or sealed off

WORKING AT HEIGHT checklist items:
  Section: "Equipment"
    — Access equipment inspected and fit for purpose
    — Scaffold or MEWP has current inspection certificate (LOLER)
    — Harness and lanyard inspected (if required)
    — Ladder secured at top and/or footed
  Section: "Area"
    — Exclusion zone established below work area
    — Signage in place warning of overhead work
    — Tools secured to prevent falling objects (tethers)
  Section: "PPE"
    — Hard hats for those below
    — Safety harness fitted and anchored (at 2m+)
  Section: "Authorisation"
    — Operative holds valid working at height training
    — MEWP operator has valid IPAF licence (if MEWP in use)
    — Weather conditions assessed and acceptable

ELECTRICAL ISOLATION checklist items:

  Section: "Atmospheric Testing"

  Section: "Emergency Arrangements"
    — Rescue plan documented and communicated
    — Rescue equipment on site (harness, winch, BA sets)
    — Rescue team identified and briefed
    — Emergency services number confirmed and accessible
    — Attendant stationed outside at all times
  Section: "Entry Controls"
    — Entry register being maintained
    — Communication system between entrant and attendant confirmed
    — Entrant briefed on entry and emergency procedures
  Section: "Authorisation"
    — Confined space risk assessment completed
    — Entrant has confined space training certificate

All endpoints enforce business rules on status transitions:

PATCH /api/ptw/:id/checklist/:checklistItemId
  Body: { response: 'yes' | 'no' | 'na', notes?: string }
  — Update a single checklist item response
  — Only allowed when permit status = 'draft' or 'submitted'
  — Record respondedById = current user, respondedAt = now()

PATCH /api/ptw/:id/submit
  — Submits permit for authorisation.
  — Validates: 
    * All required checklist items have response ('no' items must 
      have a note explaining the mitigating control)
    * Work description is not empty
    * plannedStartDate is today or future
    * Contractor or staff member is specified
  — Sets status = 'submitted'
  — Sends email to all users with 'manager' or 'admin' role:
    Subject: "📋 Permit-to-Work Requires Authorisation — [TYPE] [NUMBER]"
    Body: Who is doing what work, where, when, link to review

PATCH /api/ptw/:id/authorise
  Body: { authNotes?: string }
  — Authorises the permit. Only users with admin/manager role.
  — Cannot authorise own permit (if same person created it).
  — Sets: status = 'authorised', authorisedById, authorisedByName, 
    authorisedAt
  — Sends confirmation email to permit creator and contractor/staff.

PATCH /api/ptw/:id/reject
  Body: { rejectionReason: string } (required)
  — Rejects permit. Sets status = 'draft' (can be resubmitted).
  — Records rejectedById, rejectedAt, rejectionReason.
  — Sends email to permit creator explaining rejection reason.

PATCH /api/ptw/:id/activate
  — Marks work as started. Sets status = 'active', actualStartAt = now().
  — Only allowed if status = 'authorised' AND now() is within 
    permitValidFrom → permitValidUntil window.
  — If now() is outside the window: return 400 with error:
    "Permit validity window has passed. A new permit must be issued."

PATCH /api/ptw/:id/suspend
  Body: { suspensionReason: string } (required)
  — Temporarily stops work. Sets status = 'suspended'.
  — Sends alert email to all admins/managers.

PATCH /api/ptw/:id/close
  Body: { closureNotes: string, workCompletedSatisfactorily: boolean }
  — Closes the permit. Sets status = 'completed', actualEndAt = now().
  — If workCompletedSatisfactorily = false: flag for review.
  — Sends completion notification to admins.

STEP B9 — BACKEND: Daily cron for PTW expiry
────────────────────────────────────────────────────────────────────

Daily cron at ptwAlertHour:

  1. EXPIRE overdue permits:
     Find all permits where:
       - status = 'authorised' (not yet activated)
       - permitValidUntil < NOW()
     Set status = 'expired' on each.
     Send email to permit creator and admins:
     Subject: "⚠ Permit-to-Work Expired — [NUMBER] [TYPE]"
     Body: Permit details, work not started, new permit required.

  2. OVERDUE CLOSURE alerts:
     Find all permits where:
       - status = 'active'
       - permitValidUntil < NOW()
       - overdueClosureAlertedAt IS NULL
     Send URGENT email:
     Subject: "🚨 Permit-to-Work OVERDUE — Work Not Closed — [NUMBER]"
     Body: Work was authorised until [TIME], permit has not been 
           closed. Action required immediately.
     Set overdueClosureAlertedAt = NOW()

  3. UPCOMING expiry warning:
     Find all permits where:
       - status IN ('authorised', 'active')
       - permitValidUntil <= NOW() + 2 hours
       - expiryAlertedAt IS NULL
     Send warning email:
     Subject: "⏰ Permit-to-Work Expiring in 2 Hours — [NUMBER]"
     Set expiryAlertedAt = NOW()
