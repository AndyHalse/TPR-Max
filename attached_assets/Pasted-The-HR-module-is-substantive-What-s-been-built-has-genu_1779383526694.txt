Replit Prompt — HR Safety Fixes (Three Issues)
PROMPT: Fix three safety/compliance issues in the HR module

Context

The HR module has three bugs that need fixing before it's safe to demonstrate to enterprise customers. All three are small code changes.

Fix 1 — DBS Records: change hard delete to soft delete

File: server/routes/hrDbs.ts

Currently line ~126 runs DELETE FROM staff_dbs WHERE id = $1. Change this to a soft delete:

// BEFORE:
await pool.query(`DELETE FROM "${schemaName}".staff_dbs WHERE id = $1`, [req.params.id]);

// AFTER:
await pool.query(
  `UPDATE "${schemaName}".staff_dbs SET deleted_at = NOW(), updated_at = NOW() WHERE id = $1`,
  [req.params.id]
);
Also update every SELECT query in this file that reads from staff_dbs to add AND deleted_at IS NULL to the WHERE clause. Check the GET /api/staff/:staffId/dbs, the cron helper sendDbsExpiryReminders, and GET /api/dbs/expiry-alerts — all three need the filter.

If the staff_dbs table doesn't already have a deleted_at column, add it via a raw SQL migration at the top of registerHrDbsRoutes using ensureColumn or a CREATE TABLE IF NOT EXISTS pattern (matching the approach used elsewhere in the codebase).

Fix 2 — Confidential Documents: enforce the is_confidential flag on downloads

File: server/routes/hrDocuments.ts

In GET /api/staff/:staffId/documents/:id/download, after fetching the document record, add a role check before returning the URL:

const doc = result.rows[0];
if (!doc) return res.status(404).json({ error: 'Document not found' });

// NEW: enforce confidential flag
if (doc.is_confidential && !['admin', 'hr_admin'].includes(req.user?.role || '')) {
  return res.status(403).json({ error: 'Access denied: this document is confidential' });
}

res.json({ fileUrl: doc.file_url, fileName: doc.file_name });
Also apply the same check to the main document list GET /api/staff/:staffId/documents — confidential documents should only appear in the list for admin and hr_admin roles. Add:

AND (is_confidential = FALSE OR $2 = ANY(ARRAY['admin','hr_admin']))
...passing req.user?.role as the second parameter.

Fix 3 — Right to Work: wire the blocksAccess flag to the staff QR check-in

Find the staff QR check-in endpoint (likely in server/routes/staff.ts — the route that handles staff badge scan-in). Before completing the check-in, add a Right to Work status check:

// After identifying the staff member, before recording the check-in:
const rtwResult = await pool.query(
  `SELECT is_current, expiry_date FROM "${schemaName}".right_to_work
   WHERE staff_id = $1 AND is_current = TRUE LIMIT 1`,
  [staffId]
);
const rtw = rtwResult.rows[0];
if (rtw && rtw.expiry_date) {
  const isExpired = new Date(rtw.expiry_date) < new Date();
  if (isExpired) {
    return res.status(403).json({
      error: 'Check-in denied: Right to Work document has expired. Please contact HR.',
      reason: 'rtw_expired',
    });
  }
}
This should only block entry if an RTW record exists and has an expiry date that has passed. If no RTW record exists (e.g., new starter who hasn't had it recorded yet), allow check-in and rely on the RTW expiry alert emails to prompt HR.
