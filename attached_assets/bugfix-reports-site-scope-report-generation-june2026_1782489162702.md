# Bugfix — Reports & Analytics: site-scope the report data reads (multi-site)

**`reports.ts` imports `getScopedDb` but the report generator reads every module's data with NO site filter — so for a multi-site (enterprise) customer a generated report aggregates ALL sites instead of the active site. Single-site customers are unaffected. Test customers only. NO `npm run db:push` needed.**

> Note: this is the **per-customer Reports & Analytics** feature (each report is for the user's current site context). It is NOT the enterprise estate-wide **Portfolio Reports** (`enterpriseReports.ts`), which is meant to span all sites by design. Do not change Portfolio Reports.

## The fix
Resolve the active site (`const { db: custDb, siteContext } = await getScopedDb(req)`) and add `scopedWhere(siteContext, <table>)` to every read of a **site-scoped** table in the report flows, so a report reflects the caller's site scope (a site_coordinator's report = their site; an enterprise_admin = their active site). In `server/routes/reports.ts`:

- The **saved reports** list — `from(isolatedSchema.reports)` at L230, L463, L564 → scope by site.
- The **report-generation data reads** in `POST /api/reports/generate` (and the `/:id/view`, `/:id/email` flows):
  - `hs_incidents` (L257), `fire_risk_assessments` (L273), `permit_to_work` (L285), `ra_builder_assessments` (L297), `ppm_work_orders` (L310), `audit_records` (L324) → add `scopedWhere`.
  - `room_bookings` (L1056) → add `scopedWhere`.
- Each report's header/metadata should state the site (or "All sites" only when the caller is genuinely estate-scoped) so the output is unambiguous.

**Leave customer-level tables unscoped** (they are not site-scoped): `company_settings` (L920/947/968), `email_log` (L933/953). Do not scope those.

## Acceptance criteria
- A report generated by a site_coordinator contains ONLY their site's records (H&S, FRA, PTW, RA, PPM, audits, room bookings); an enterprise_admin's report reflects their active site.
- For a multi-site customer, no report silently mixes data from sites the caller isn't scoped to.
- Single-site customers: reports unchanged (one default site = no-op).
- The enterprise Portfolio Reports feature is untouched.

## Do NOT
- Do not scope `company_settings` or `email_log` (customer-level).
- Do not change `enterpriseReports.ts` (estate-wide by design).
- Do not regress single-site customers.
