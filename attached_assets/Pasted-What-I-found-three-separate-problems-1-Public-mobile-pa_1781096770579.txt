What I found — three separate problems
1. Public mobile pages are blocked entirely (most serious). Two flows are used by people on their phones via a link or QR code — they've never logged into the admin app, so they have no CSRF cookie at all:

Audit Mobile (AuditMobile.tsx) — external auditors filling in an audit via a shared link. Every answer save, photo upload, and final submit hits /api/audits/public/..., which is not on the server's exemption list. They'll get a 403 on everything.
Induction checkpoints (InductionCheckpoint.tsx) — inductees scanning QR checkpoints and reporting hazards. Same story: /api/induction/checkpoint/... isn't exempt.
Other public flows (kiosk, NDA signing, fire marshal, worker document upload) were correctly added to the exemption list in server/index.ts:295-315 — these two were simply missed. Both are already protected by a secret token in the URL, so exempting them is safe.

2. About 17 admin screens make raw requests without the token. Most of the app goes through a shared helper (apiRequest in queryClient.ts) that attaches the token automatically and even retries once if it's stale. But these files call fetch directly and never attach it — so the button looks fine but fails with a 403: ID Card Designer (both versions), Thermal Pass Designer, CO2 Tracker, Help panel feedback, H&S Template Editor and template reset, all three AI analysis tools, visitor emergency-notify on the Dashboard, Martyn's Law evidence upload, data import in System Settings, roughly ten calls in Integration Settings (Paxton, BioStar, API keys), the induction scene photo upload, and the test-worker generator.

3. The Billing page is broken in a different way. Billing.tsx and one call in EditContractorWorkerModal.tsx call the shared helper with the arguments in the wrong order — apiRequest(url, options) when it expects apiRequest(method, url, data). The "Manage billing" and "Upgrade" buttons can't work at all. That's a revenue-path bug.

Things I checked that are fine: document uploads that PUT to a signed storage link (those bypass the server, no token needed), the muster QR scanner (uses fire-marshal credentials, exempt), and the Super Admin page (uses the helper correctly).

Prompt 1 — Unblock public audit and checkpoint pages (do this first)

In server/index.ts, the CSRF middleware (createCSRFMiddleware, around lines 295–315) has a skip list for public endpoints that are accessed from mobile devices without an admin session. Two public flows were missed and are currently broken for real users — every mutating request gets 403 CSRF_INVALID:

/api/audits/public/ — used by external auditors via a shared link (PUT autosave, POST upload, POST submit, defined in server/routes/auditEngine.ts). Protected by a secret URL token plus auditPublicRateLimit.
/api/induction/checkpoint/ — used by inductees scanning QR checkpoints on their phones (POST scan, POST report-hazard, POST hazard-photo, defined in server/routes/induction.ts around lines 5152–5234). Protected by the secret qrToken.
Add both prefixes to the existing req.originalUrl.startsWith(...) skip block (the one that already lists /api/kiosk, /api/nda/public, /api/worker-doc-request/ etc.) with a comment explaining they are token-protected public mobile endpoints. Do not change anything else in the middleware. Then verify by simulating: a POST to /api/audits/public/some-token/submit with no cookies must NOT return 403 CSRF_INVALID, and a POST to a normal admin endpoint like /api/staff with no token must still return 403.
