Extend the Compliance Dashboard (server/routes/complianceDashboard.ts and
client/src/pages/ComplianceDashboard.tsx) to cover compliance data points that
exist in the database but are not currently read. Follow the existing pattern
exactly: each new category in its own try/catch that logs a warning and
continues (non-fatal), feeding criticalIssues, warnings, expiryTimeline,
contractorRiskMap and a per-category score (expired = critical, expiring
within 30 days = warning, otherwise compliant; empty category = score 100).

ADD THESE CATEGORIES:

1. Extend "Contractor Insurance" (existing section): also check
   professional_indemnity_expiry_date, health_safety_policy_expiry_date,
   chas_expiry_date and safe_contractor_expiry_date on contractor_companies,
   using the same checkInsurance helper with appropriate labels. Only count
   CHAS/SafeContractor when the corresponding *_certified flag is true.

2. NEW "Worker Right to Work": for active contractor_workers who have visited
   in the last 12 months (reuse the activeWorkerIds set already built in the
   inductions section), check right_to_work_status and
   right_to_work_expiry_date. Expired date or status 'expired'/'invalid' =
   critical; status 'pending' or expiring ≤30 days = warning. Link path
   /contractors. Attribute issues to the worker's company in contractorRiskMap.

3. NEW "Worker DBS": from contractor_worker_dbs (is_current = TRUE,
   deleted_at IS NULL) joined to contractor_workers, check policy_expiry_date
   (expired = critical, ≤30 days = warning). Also flag any active worker with
   dbs_required = TRUE who has no current DBS record (warning). Link path
   /contractors.

4. NEW "Worker Certifications": from contractor_documents where worker_id IS
   NOT NULL, is_active = TRUE and expiry_date IS NOT NULL, joined to
   contractor_workers for the name. Expired = critical, ≤30 days = warning,
   timeline category 'Worker Certifications'. Link path /contractors.
   Attribute to the worker's company in contractorRiskMap.

5. NEW "Equipment": from contractor_equipment (is_active = TRUE) joined to
   contractor_documents via equipment_id for certificates (LOLER, PUWER, PAT,
   MOT etc.). Expired certificate = critical, ≤30 days = warning. Also flag
   active equipment with no certificate documents at all as a warning
   ("no certification on record"). Link path /contractors (or the equipment
   page route if one exists — check the client router).

6. NEW "Staff DBS": from staff_dbs (is_current = TRUE, deleted_at IS NULL)
   joined to staff (is_active = TRUE), check policy_expiry_date. Link path /hr.

7. NEW "Staff Training": from staff_training_records joined to
   training_requirements, mandatory training only, for active staff — mirror
   the expiring/expired logic already used in server/routes/hrDashboard.ts.
   Expired mandatory training = critical, expiring ≤30 days = warning.
   Link path /hr.

8. Extend "Audits": also flag audit_corrective_actions with status = 'open'
   and due_date in the past as critical ("Corrective action overdue").

9. NEW "Document Approvals": count contractor_documents with status =
   'pending' and is_active = TRUE as warnings ("document awaiting approval")
   — no score impact beyond the warning list is fine, but show the count.
