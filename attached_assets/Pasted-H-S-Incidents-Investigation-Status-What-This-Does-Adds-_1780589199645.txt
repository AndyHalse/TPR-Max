H&S Incidents: Investigation Status

What This Does

Adds an investigation lifecycle to incident and near miss records: Open → Under Investigation → Closed. Right now an incident is logged and RIDDOR-assessed, but there's no way to track whether it's actually been investigated. H&S managers need this to demonstrate due diligence and manage their workload.

This is separate from the Good Spot resolve workflow — BBS records (good_spot/positive_action) already have their own resolved flag and are not affected by this change.

1. Database Changes

In ensureHsIncidentsTable (server/routes/hsIncidents.ts)

Add three new columns after the existing ALTER TABLE block:

await pool.query(`ALTER TABLE "${schemaName}".hs_incidents ADD COLUMN IF NOT EXISTS investigation_status TEXT NOT NULL DEFAULT 'open'`);
await pool.query(`ALTER TABLE "${schemaName}".hs_incidents ADD COLUMN IF NOT EXISTS investigated_by TEXT`);
await pool.query(`ALTER TABLE "${schemaName}".hs_incidents ADD COLUMN IF NOT EXISTS investigation_notes TEXT`);

Valid values for investigation_status: 'open' | 'investigating' | 'closed'

Default is 'open' — all new and existing incident/near miss records start as open.

In isolatedSchema.ts

Add to the hsIncidents Drizzle table definition:

investigationStatus: text('investigation_status').notNull().default('open'),
investigatedBy: text('investigated_by'),
investigationNotes: text('investigation_notes'),



2. Backend Changes (server/routes/hsIncidents.ts)

POST handler

After the isBbs variable is set, add:

const investigationStatus = (!isBbs && !isNearMiss && body.investigationStatus) ? body.investigationStatus : 
  (!isBbs ? (body.investigationStatus || 'open') : null);

Wait — simpler: BBS records don't use investigation_status. For incident and near_miss, accept from body or default to 'open':

// Investigation fields — only for incident and near_miss
const investigationStatus = (!isBbs) ? (body.investigationStatus || 'open') : 'open';
const investigatedBy = (!isBbs) ? (body.investigatedBy || null) : null;
const investigationNotes = (!isBbs) ? (body.investigationNotes || null) : null;

Include these in the .values({...}) insert:

investigationStatus,
investigatedBy,
investigationNotes,

PUT handler

Same: accept body.investigationStatus, body.investigatedBy, body.investigationNotes and include in the updates object for non-BBS records:

if (!isBbs) {
  updates.investigationStatus = body.investigationStatus || 'open';
  updates.investigatedBy = body.investigatedBy ?? null;
  updates.investigationNotes = body.investigationNotes ?? null;
}

The resolved / resolvedBy / resolvedAt fields on BBS records — completely separate system.
