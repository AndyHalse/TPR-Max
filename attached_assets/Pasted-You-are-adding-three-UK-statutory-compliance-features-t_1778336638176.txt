SECTION 1 — RIDDOR CLASSIFICATION (Reporting of Injuries, Diseases 
and Dangerous Occurrences Regulations 2013)
════════════════════════════════════════════════════════════════════════

LEGAL CONTEXT:
Under RIDDOR 2013, employers must report certain workplace incidents 
to the HSE (Health and Safety Executive). Failure to report is a 
criminal offence carrying unlimited fines.

Reportable categories and deadlines:
  - Fatality:                  Report IMMEDIATELY (same day)
  - Specified injury*:         Report within 10 days
  - Over-7-day incapacitation: Report within 15 days
  - Dangerous occurrence:      Report within 10 days
  - Occupational disease:      Report when diagnosis confirmed

*Specified injuries include: fractures (not fingers/thumbs/toes), 
amputations, permanent loss of sight, crush injuries, scalping, 
unconsciousness, requiring resuscitation, admittance to hospital 
for over 24 hours.

STEP 1B — BACKEND: RIDDOR deadline calculation utility
────────────────────────────────────────────────────────────────────

Create /server/utils/riddorUtils.ts:

  export type RIDDORCategory =
    | 'fatality'
    | 'specified_injury'
    | 'over_7_day'
    | 'dangerous_occurrence'
    | 'occupational_disease'
    | 'not_riddor_reportable'

  export function calculateRIDDORDeadline(
    category: RIDDORCategory,
    incidentDate: Date
  ): Date | null {
    const d = new Date(incidentDate)
    switch (category) {
      case 'fatality':
        return d  // Same day — deadline IS the incident date
      case 'specified_injury':
      case 'dangerous_occurrence':
        d.setDate(d.getDate() + 10)
        return d
      case 'over_7_day':
        d.setDate(d.getDate() + 15)
        return d
      case 'occupational_disease':
        return null  // On diagnosis — not date-based
      default:
        return null
    }
  }

  export function getDaysUntilRIDDORDeadline(deadline: Date): number {
    const now = new Date()
    const diff = deadline.getTime() - now.getTime()
    return Math.ceil(diff / (1000 * 60 * 60 * 24))
  }

  export function isRIDDOROverdue(deadline: Date | null): boolean {
    if (!deadline) return false
    return new Date() > deadline
  }

STEP 1D — BACKEND: RIDDOR reminder cron job
────────────────────────────────────────────────────────────────────

Add a daily cron job (alongside the existing CDM and contractor 
expiry cron jobs) that runs at 07:00 every morning:

  Find all incidents where:
    - riddor_category IS NOT NULL
    - riddor_category != 'not_riddor_reportable'
    - riddor_category != 'occupational_disease'
    - riddor_reported_at IS NULL       (not yet reported)
    - riddor_reminder_sent_at IS NULL  (reminder not yet sent)
    - riddor_reporting_deadline IS NOT NULL

      (deadline hasn't passed by more than 1 day)
    - (deadline - NOW()) <= INTERVAL '5 days'
      (within 5 days of deadline)

  For each matching incident, send an email to the customer's 
  admin users:

  Subject: "⚠ RIDDOR Reporting Reminder — Action Required"

  Body (plain text for reliability):
  ---
  This is an automated reminder from TPR Max.

  An incident recorded on [INCIDENT DATE] at [SITE NAME] may require 
  reporting to the HSE under RIDDOR 2013.

  Incident: [TITLE/DESCRIPTION]
  Category: [RIDDOR CATEGORY — human readable]
  Reporting deadline: [DATE]
  Days remaining: [N]

  To report this incident to the HSE, visit:
  https://www.hse.gov.uk/riddor/report.htm

  Once reported, log in to TPR Max and mark this incident as 
  reported to record your HSE reference number.

  This reminder will not be sent again for this incident.
  ---

  After sending, set riddor_reminder_sent_at = NOW() to prevent 
  duplicates.

  For FATALITY incidents: send the email immediately on incident 
  creation, not via the daily cron. Subject: 
  "🚨 URGENT — Fatal Incident Requires Immediate HSE Notification"

SECTION 2 — NEAR MISS REPORTING
(Management of Health & Safety at Work Regulations 1999, Reg 5)
════════════════════════════════════════════════════════════════════

LEGAL CONTEXT:
Employers must implement procedures for reporting near misses 
(unplanned events that did not result in injury but had the 
potential to do so). Near miss data is used to identify hazards 
before injuries occur. Under MHSWR 1999, risk assessment must be 
reviewed when near misses indicate a hazard has changed.

This is quick to add — near miss classification onto the existing 
incident report system.

SECTION 3 — FIRE RISK ASSESSMENT TRACKING
(Regulatory Reform (Fire Safety) Order 2005)
════════════════════════════════════════════════════════════════════

LEGAL CONTEXT:
The RRO 2005 requires every non-domestic premises to have a 
documented Fire Risk Assessment (FRA) carried out by a competent 
person. The FRA must be:
  - Documented (if 5+ employees)
  - Reviewed regularly (annually recommended, or after significant 
    changes to premises, occupancy, or processes)
  - Available for inspection by the Fire Service

Failure to have a valid, current FRA is a criminal offence.

────────────────────────────────────────────────────────────────────
STEP 3A — DATABASE: Fire risk assessment table
────────────────────────────────────────────────────────────────────

Create a new table:

  CREATE TABLE IF NOT EXISTS fire_risk_assessments (
    id              SERIAL PRIMARY KEY,
    customer_id     INTEGER NOT NULL REFERENCES customers(id),
    title           TEXT NOT NULL DEFAULT 'Fire Risk Assessment',
    assessor_name   TEXT NOT NULL,        -- Name of competent person
    assessor_company TEXT,                -- External assessor company
    assessment_date DATE NOT NULL,        -- Date FRA was carried out
    next_review_date DATE NOT NULL,       -- Date FRA must be reviewed by
    document_url    TEXT,                 -- Uploaded FRA document URL
    status          TEXT NOT NULL DEFAULT 'current',
      -- Values: 'current' | 'review_due' | 'overdue' | 'superseded'
    findings_summary TEXT,               -- Key findings / action points
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    updated_at      TIMESTAMPTZ DEFAULT NOW(),
    reminder_sent_at TIMESTAMPTZ          -- Prevents duplicate reminders
  );
