## What you might be missing
A few things worth confirming before this goes into Replit:
1. **2FA scope**: The prompt applies 2FA to ALL customer users who log in. If you only want it for admin-role users (not regular staff), that's a small tweak — just add a `role === 'admin'` check before triggering the code. Worth deciding now.
2. **Add-on modules default OFF**: I've kept PPM, Audit Engine, Compliance Certs, Permit to Work, RA Builder, and Help Desk as default OFF for new and existing customers — these seem to be paid add-ons. Platform admin can then enable them per customer. Is that right, or should everything be ON by default?
3. **The existing PPM toggle behaviour changes**: Currently, toggling PPM in the platform admin edit modal writes directly into the customer's `company_settings`. After this change, the platform admin sets a "lock" and the customer's own toggle is separate. Existing customers with PPM enabled in `company_settings` will still have it enabled — you just now also have a lock mechanism. This is backward-compatible.
4. **Email address required for 2FA**: If any of your existing customer admin accounts don't have an email address stored, they'll skip 2FA. Worth checking your existing customers have emails set.
5. **No 2FA for the platform admin login**: The prompt deliberately leaves your own `/platform-admin/login` without 2FA. If you want 2FA on your own admin login too, that's a separate, simpler addition (it's a single known login with one admin account).
