Behaviour-Based Safety: Good Spot & Positive Action Reporting

What This Feature Does

This extends the existing H&S Incidents module (/hs-incidents) to support Behaviour-Based Safety (BBS) reporting — specifically two new positive report types that sit alongside incident and near miss records:





Good Spot — someone notices a hazard and reports it (e.g. cable out of its conduit, spilt liquid on stairs, missing guard rail). Passive positive behaviour.



Positive Action — someone notices a hazard AND arranges for it to be fixed themselves. Active positive behaviour.

These are completely separate from incidents and near misses. They have no RIDDOR category and no injured person — because nothing went wrong. They're about recognising proactive safety behaviour.

The goal is to give management a Safety Engagement Dashboard that shows the ratio of positive reports to incidents over time — which is a far more useful indicator of safety culture than raw incident counts alone.

1. Database Changes

New columns on hs_incidents table

Add these columns. The ensureHsIncidentsTable function already uses CREATE TABLE IF NOT EXISTS — add ALTER TABLE ... ADD COLUMN IF NOT EXISTS statements for the new columns immediately after the existing CREATE block. Follow the same pattern used elsewhere in the codebase.

record_type          TEXT NOT NULL DEFAULT 'incident',
  -- values: 'incident' | 'near_miss' | 'good_spot' | 'positive_action'

hazard_type          TEXT,
  -- reuses the same hazard type values as near_miss_hazard_type
  -- used for good_spot and positive_action records

resolved             BOOLEAN NOT NULL DEFAULT FALSE,
resolved_by          TEXT,
resolved_at          TIMESTAMPTZ,
resolution_notes     TEXT
  -- resolution fields: used for good_spot and positive_action records only

Data migration

In ensureHsIncidentsTable, after adding the new columns, run this once:

UPDATE {schemaName}.hs_incidents
SET record_type = 'near_miss'
WHERE is_near_miss = TRUE AND record_type = 'incident';

This safely migrates existing near miss records to the new record_type field without touching anything else.

isolatedSchema.ts

Add the four new fields to the hsIncidents Drizzle schema definition to match the new columns:
